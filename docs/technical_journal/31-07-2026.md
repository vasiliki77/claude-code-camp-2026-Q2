# 31-07-2026

Steps 3, 4 and 5 ported Ruby → Python. Built a port skill; the eval loop for it was too costly and slow to finish.

## Step 3 (Prompt Builder)

- Ported `PromptBuilder`, `Backends::Base`, five backends (Anthropic, OpenAI, Gemini, Ollama, OllamaCloud), `UnsupportedModelError`.
- `prompts/system.md` and `Config.PROMPTS_DIR` returned after being deleted in step 1.
- **Truthiness trap:** Ruby's `estimate_cost` guards with `unless a && b`. `0.0` is truthy in Ruby, falsy in Python — a literal port returns "no price" for every local Ollama model (all cost `0.0`). Guard is `is None`.
- **Ollama `__init__` params reordered.** Ruby allows a required keyword after a defaulted one; Python does not. Both keyword-only, so call sites unchanged.
- **`model_info` name collision.** Ruby has a class method and an instance method with the same name; Python can't. Classmethod kept the name, instance data moved to `self.info`.
- **Mirrored a Ruby bug:** `PromptBuilder#to_messages` passes only `messages`, but OpenAI/Ollama/OllamaCloud take `(system, messages)` — broken for 3 of 5 backends. Unchanged through Ruby step 12, so ported as-is and documented.
- Verified: stdout `diff` empty. Also dumped all five backends' payload/headers/url/cost metadata from both languages and diffed — identical. The example only exercises Anthropic; this covered the other four.
- `json.dumps(indent=2)` matches `JSON.pretty_generate` byte-for-byte. Passing `ensure_ascii=False` for future non-ASCII prompts.

## Step 4 (API Client)

- Ported `Client` (stdlib `urllib.request`, not `requests` — the Ruby README's no-library stance is the point of the step) and `ApiError`. `requirements.txt` unchanged.
- **The stdout gate broke here.** The example makes a live API call: non-deterministic wording, token counts, and `id` per run, and it costs money. `diff <(ruby) <(python)` would fail on two correct implementations.
- Replaced with four checks: 6-line deterministic prefix diff; response top-level key-set comparison; a bogus-key 401 (not retryable, so free) exercising `ApiError`; an offline `http.server` covering retry/backoff.
- **Structural trap:** `urllib.error.HTTPError` subclasses `URLError`. Caught in the wrong order, every 500 is swallowed as a transient connection error and the status-code retry list never runs.
- Ruby's `verify_mode` / `ca_file` / the macOS-vs-Linux cert section have no Python equivalent — `urlopen` verifies against the system trust store by default.
- Added an explicit `timeout=60` Ruby didn't need: Ruby inherits `Net::HTTP`'s 60s defaults, `urlopen` blocks forever.
- Retry policy confirmed: 4 total attempts, backoff 0.5/1.0/2.0, retryable `[408,409,429,500,502,503,504]`.
- **Upstream Ruby bug found:** `PROMPTS_DIR` changed to `../../../prompts`, resolving to `week1_baseline/ruby/prompts` — a directory that does not exist, while the `prompts/system.md` it should find sits inside the step. Present in every Ruby step 04–11. Masked because `prompt_override.system: true` routes to `.boukensha/`. Python keeps the correct `parents[1]`; Ruby left untouched.
- **Ruby caught up to Python:** `tasks/base.rb`'s two changes (`settings.yml` → `settings.yaml` in an error message, a Hash guard in `fetch`) were already in the Python since step 0. No Python edit.

## Step 5 (Agent Loop)

- **Delta was far larger than "an `agent.rb` file being added."** All five backends changed, plus `client.rb`, `prompt_builder.rb`, `tasks/base.rb`, `errors.rb`, `boukensha.rb`.
- Every backend gained `parse_response`, normalizing its provider's reply into one shape. Four gained the inverse (`_assistant_message` / `_assistant_parts`) to replay history. Anthropic needs neither — its `content` array is both the normalized shape and the wire format.
- Gemini, Ollama and OllamaCloud assign no tool-call IDs; they reuse the function name as the `id`.
- **Two truthiness traps, both guarded with `is None`:**
  - `_call_opts` — an explicit `max_output_tokens=0` is forwarded in Ruby (truthy), dropped by a Python truth test.
  - backends' `tools` param — `wrap_up` disables tools by passing `tools=[]`. Written as `tools or to_tools(...)`, the empty list is falsy, the full tool set returns during the one call meant to stop the agent, and the iteration ceiling silently does nothing.
- **The cross-language check caught a real bug I wrote.** Ruby's `#to_json` emits compact `{"path":"x"}`; Python's default `json.dumps` emits `{"path": "x"}`. That string goes on the wire as OpenAI's `function.arguments`. Fixed with `separators=(",", ":")`. Nothing in the Anthropic-only example would have surfaced it.
- Added a `dig()` helper to `backends/base.py` for Ruby's `Hash#dig` — a bare Python index chain raises where Ruby returns `nil`.
- **Accepted divergence:** the `tool call → …` log line. Ruby 3.4 prints `{"path" => "."}`, Python prints `{'path': '.'}`. The Ruby README shows a third format from an older Ruby, so the rendering isn't stable within Ruby either. Human-readable logging in already non-deterministic output; not worth pinning.
- `LoopError` is declared in Ruby and never raised or rescued. Ported for surface parity, flagged unused.
- `config.rb`'s diff is Ruby 3 endless-method sugar only — no Python change.
- Verified: 9-line prefix diff; cross-language normalization byte-identical (8 canned inputs × 5 backends, plus `to_payload`, `to_payload(tools=[])`, wrap-up directive, defaults); offline loop test (7 assertions incl. assistant-before-tool_result ordering, ceiling → exactly one wind-down call with `tools=[]`/400 tokens without incrementing the counter, `ApiError` and blank-text fallbacks); live smoke test, both exit 0.

## Skills: tried, too costly and slow

- Built `.claude/skills/ruby-to-python-port/` — `SKILL.md`, `references/translation.md` (Ruby→Python idiom catalogue), `references/plan-template.md`.
- Tried to validate it with the skill-creator eval loop: two subagents on step 04, one with the skill, one baseline.
- **Too expensive for the value.** Each subagent starts cold and re-derives context already in the session. The baseline spent **61,235 tokens / ~234s and produced no plan** — it stopped to ask a clarifying question. Both runs were killed; zero artifacts.
- **The baseline found the same things unaided** — the `PROMPTS_DIR` bug, the live-API-gate problem, the stdlib `urllib` call. The skill's marginal value was never demonstrated.
- Switched to writing plans directly in-session. That produced the step 04 and 05 plans at a fraction of the cost.
- Two smaller issues: a skill created mid-session isn't in the registry (loaded at startup), and the eval workspace was wrongly placed inside `.claude/skills/`, which is a discovery namespace, not scratch space.
