## The framing the week turned on

- **Two audiences read the telemetry, and only one of them is us.** Agent telemetry answers "is the agent working and what does a run cost"; journey telemetry answers Arcane Loop's actual question about where players get confused, blocked, bored or overpowered. **The telemetry *is* the product here** — the report is a rendering of the agent's own event stream — which inverts the usual priority order and makes the journey stream a first-class artifact rather than a by-product.
- **The requirement binding both is attribution.** When the agent stops making progress that is either a game defect (a finding) or an agent defect (a bug), and every claim handed to QnA is worthless if the two cannot be separated. **That is the whole reason Layer 1 comes before Layer 2** — the agent stream is the control the journey stream is read against.

## What the 62 session files actually say

Measured across `.boukensha/sessions/*.jsonl` and the step-12 sources, not assumed.

- **`tool_result.ok` lies, and the codebase already knew.** `agent.rb:203` (and `agent.py:290`) logs `ok: true` unless the tool *raises* — but the standard tools never raise, they return `"error: #{msg}"` from the `oops` lambda at `tools/shell.rb:31` and `tools/file_system.rb:43`. An observed `run_command` 30s timeout is recorded `"ok": true`. **Any error rate derived from the flag undercounts exactly the failures that look like the agent getting stuck.** `file_system.rb` then pattern-matches that same string prefix in five places — the codebase invented an error type and checks it by `start_with?`.
- **Zero of 62 sessions record how they ended.** `Logger#close` closes the IO and writes nothing, so a clean exit, a `SIGINT` and a crash inside the agent loop are byte-identical on disk — **the same shape a blocked player journey has.**
- **85% of the largest session file is re-serialized history.** `Logger#prompt` writes the entire message list every iteration: 191 KB of a 224 KB file. Growth is quadratic in turn length, and Layer 2 makes runs longer. `log_viz` reads only `messages.last`, and only when it is a user message (`log_viz/lib/log_viz/session.rb:77–86`), so this is fixable with no change to the viewer.
- **`limit_reached` and `compaction` have never once fired — 0 occurrences in 62 sessions.** Both are implemented; neither has executed. This puts a number on the new uncertainty recorded at the end of [week 1](week1.md), and makes forcing both paths a gate *before* any long mapping run rather than a discovery during one.
- **API failures emit nothing.** `agent.rb:148` rescues `ApiError` and logs `turn_end`; `Client#call` retries internally. A turn that succeeded after three 529s is indistinguishable from one that succeeded first time.

## Technology decided, and why cost was not the reason

- **Not OpenTelemetry.** Cost decides nothing here — OTel is Apache-2.0, and Jaeger, Grafana+Tempo, SigNoz, Langfuse and Phoenix all self-host at $0. What decided it: **no general-purpose tracing backend renders the deliverable** (Jaeger shows spans; it will never show that a door needs a key no reachable NPC carries), and the operational weight of a collector plus backend beside an already-Dockerised CircleMUD on WSL2 — during a week whose predecessor was largely a catalogue of silent signal failures.
- **The boundary between emission and storage stays a filesystem write, not a network hop.** An append to an open file either works or raises; a dropped OTLP export is silent. Revisit criterion recorded: when there is a genuinely distributed trace to follow. Waiting is cheap because `turn` → span, `iteration`/`tool_call` → child span is a converter over the same JSONL.
- **SQLite over DuckDB for aggregation** — the `sqlite3` CLI (3.45.3) and Python's stdlib `sqlite3` (3.46.0) are both already present, so zero installs; the Ruby gem is not, which only matters if the rollup later moves into `log_viz`. DuckDB's edge is querying the JSONL glob with no ingest step, and at 62 files / ~700 KB that advantage is worth nothing against the cost of an unfamiliar tool.
- **The ingest step pays for itself twice** — it forward-fills `turn`/`iteration` once (only their own events carry them; `log_viz` already re-derives this at `session.rb:71–76`, and every future reader would too), and NULL gives the absent-versus-zero rule for free, since an unmeasured error rate and a zero error rate are different claims.
- `.boukensha/sessions.db*` added to `.gitignore` — **the JSONL stays tracked as the source of truth, the database is a cache over it.** Verified with `git check-ignore` against both the `.db` and its `-wal` sidecar.

## Scope cut to the minimum effective path

- **The week is self-directed, so the plan was trimmed to the shortest route that still produces the deliverable.** In: `session_end`, a truthful `ok` flag, the `prompt` payload trim, three journey event types, one SQLite table, a Graphviz world graph, and compaction forced and observed. Out: durations, retry/error phases, a second table and canonical view, and any BI tool. Recorded as [`obs_plan.md`](../plans/observability/obs_plan.md) §5.3.
- **The cheap fix for `ok` is the right one this week** — read the MCP `isError` flag and the `error:` prefix, rather than the result-type refactor. It is correct for every tool the MUD work actually calls; the refactor stays documented for whenever a week needs it.
- **The course reference implementation uses OpenTelemetry with Docker; this project diverges.** A collector plus a tracing backend reproduces the *emission* and *trace-explorer* half of a pipeline. **The half that carries the weight here is the other one** — landing telemetry somewhere queryable, reconciling two streams on one correlation key, and serving a report off the result. That half is unaffected by whether a collector exists. Skipping it removes containers, not capability.
- **Memory work is scoped to observation, not redesign.** `Context#compact_messages!` drops the oldest 40% and snaps to a user boundary — **pure deletion, no summarization, nothing persisted**. Combined with its zero firings, the honest move is to make it run, log what it destroys, and see whether the agent re-walks ground it had already mapped. **Memory and observability turn out to be the same question from two ends:** a compaction strategy cannot be judged without telemetry showing what was dropped, and the world graph is the obvious thing to compact *into*.

## Ruby dropped, and the decision paid for itself immediately

## Implementing the three fixes

- **The `ok` flag needed a type, not a string.** `ToolFailure` subclasses `str` deliberately: a failed call must still reach the model as its own text so it can correct itself, so everything downstream keeps treating it as the string it is, and only the logger reads the type. `Client.call_tool` was *already* returning `{"text":…, "error": bool}` from the MCP `isError` flag — **`tools/mcp.py` was the one place throwing it away.**
- **The distinction that matters is confirmed end-to-end.** Against the live MUD: `look` at a nonexistent target returns *"You do not see that here."* as a plain `str` with `ok=True`, while an invalid enum returns `ToolFailure` with `ok=False`. **The tool worked; the player was blocked.** The old code called both a success, which is exactly the conflation that would have made every "blocked" finding unfalsifiable.
- **`session_end` had to be idempotent.** Both shutdown paths close in a `finally`, so a second close must not append a second ending. Unpriced sessions report `None` rather than `0.0` — an unmeasured cost and a free run are different claims, the same absent-versus-zero rule the SQLite ingest will need.
- **Telling a crash from a clean exit needed no restructuring.** `sys.exc_info()` inside a `finally` still reports the exception currently propagating. The REPL path is the exception: its `except KeyboardInterrupt` swallows the interrupt, so by the time the `finally` runs `exc_info()` is clear and the reason has to be passed explicitly. **A handled exception is invisible to the handler that runs after it.**
- **Two existing tests broke, and were wrong before they broke.** Both asserted `events[-1]["reason"]` as shorthand for "the `turn_end` event", which held only while `turn_end` happened to be last. `session_end` made them fail. They assert on identity now. Same family as the 04-08 check that could not pass: **a test that asserts position rather than identity is measuring the file, not the behaviour.**
- 108 tests pass, 12 of them new.

## The MUD was down, and the cause was ours

- The diagnosis cost more than it should have, because a MUD that accepts connections and stays silent looks like a broken MUD rather than a busy one. **Third week running that the expensive failure was a component misreporting its own state.**

## Closing the compaction gate, and two defects underneath it

- **Compaction fired for the first time ever — twice — for 4.1 cents.** Three short turns on one context, threshold overridden on the context object rather than in `settings.yaml` so an interrupted run leaves no dangerous config behind. **No 400**, the failure week 1 warned about.
- **The first attempt failed, and the failure was the finding.** Setting the threshold to 4,000 tokens should have fired at turn 2. It did not: turn 1 reported **917 tokens** when ~4.5k was in play. A turn ending on `max_iterations` calls `wrap_up`, which runs with **tools disabled**, so that final call's `input_tokens` excludes all 26 tool definitions — and `record_usage` writes it straight into `current_tokens`.
- **Compaction cannot fire mid-turn at all.** `_compact_if_needed()` sits at `agent.py:63`, outside the `while True` loop, so it is evaluated once per turn at turn start. **A mapping run is one long turn**: the 05-08 run grew 4,117 → 20,568 tokens with no opportunity to compact at any point, and a long enough one would hit the window and fail rather than compact. **This sits directly under the project's core use case.**
- **The two compound perversely.** Compaction is least likely to fire right after the turns that worked hardest, because those are the turns that end on a ceiling and therefore end with a deflated reading — turn 3 of the gate reported 948 tokens after genuinely spending 13,946.
- **It also explains the 400 that did not happen.** A mid-turn compaction is precisely the one that could orphan a `tool_result`, and mid-turn compaction currently cannot occur. **The two findings are one fact seen from opposite sides** — fixing the first makes the second reachable, so they have to be fixed together. Both deferred, both recorded in [`layer1`](../plans/observability/layer1) §1.6.1–1.6.2.

## Layer 2: parsers written against real output rather than guesses

- **The first draft would have matched nothing.** It looked for `Obvious exits:`, read off an older session's `look` output. Real move replies end `[ Exits: n s ]` — **0 of 66 moves** would have parsed. The corpus was the difference between a parser and a plausible-looking one.
- **A room is identified by its exit line, not by the shape of its first line.** Guessing from punctuation misfiles `You are 18 years old.` — a score readout — as a room. There is a test pinning exactly that.
- **The direction of a blocked move is not in the reply.** *"The door seems to be closed."* never says which door. It has to come from the tool call's arguments, which is why the parser takes them alongside the text.
- **Dark rooms were being dropped silently.** `It is pitch black...` is a *successful* move — discarding it loses the node **and** the edge that reached it, leaving a hole in the graph that looks like the agent never moved. Emitted now with `room: None, dark: True`; a placeholder name would collapse every unlit room into one node and invent edges between unrelated places.
- **The status prompt is free telemetry.** `22H 100M 83V` on the end of every single reply is hit/mana/movement — progression and combat-risk signal at no extra cost.
- **74 of 88 calls parse**: 61 `room_entered` across 30 distinct rooms, 7 `command_rejected`, 6 `movement_blocked`. The 14 silent ones are correctly silent — score readouts, `poll`, `set_position`.
- **The most interesting result was not predicted.** **5 of 6 blocks are `level_gated`** — *"This zone is above your recommended level."* That is not a puzzle, it is a progression wall, and it is exactly the kind of finding the brief asks for. It only shows up because `movement_blocked` carries a `reason`; a single "blocked" count would have hidden it inside the door.

## Deriving journey events at ingest instead of emitting them live

- **Two plan steps collapsed into one.** `obs_plan.md` §4.1 weighed three emission points; the plan had chosen B (live, in the MCP wrapper). Taking **C** instead — parse at ingest — needs no agent change, no re-run, and **applies the parsers retroactively to all 66 archived sessions**, including the 62 recorded before Layer 2 existed. `tool_result` already carries the MUD's full reply, so nothing is lost by parsing after the fact.
- **With no API budget left, the cheapest correct option was also the better one.** Live emission stays a small change, worth doing when something needs to *react* to a journey event during a run rather than read it afterwards.
- **1,164 rows from 66 sessions**, one SQLite table, rebuilt from scratch every time rather than appended to.
- **`turn` had to default to 1, not NULL.** Only the REPL emits `turn` events, so forward-filling from those alone left every row of a one-shot run NULL — and `COUNT(DISTINCT turn)` then reported **0 turns for 80 iterations of work**. Every event after `session_start` belongs to some turn, and the first is 1 on both paths.
- **All 90 journey rows carry `turn` and `iteration`**, which is `obs_plan.md` §7's Layer 2 gate: every journey event resolves back to the agent stream that produced it.

## Layer 3: the map, and the week's first real finding

- **`The Dirt Path` refuses movement in all four advertised directions.** Every exit answers *"This zone is above your recommended level."* — **five of the corpus's six blocks are in that one room**. A low-level player who walks in can only leave the way they came. **Nothing about this was predicted**; it fell out of attaching blocks to rooms.
- **The finding only exists because the graph knows where the player was standing.** A `movement_blocked` event carries the direction and the refusal but *never the origin* — the origin only exists once movements are folded into a path. A room list could not have produced this; neither could the SQL report, which groups by reason and direction and shows the shape of the problem without its location.
- **§4.2 was settled by counting, not arguing.** 72 room entries, **32 distinct titles, 36 distinct (title, exits) pairs**. Three titles cover more than one room — `The Great Field Of Midgaard` appears with both `ns` and `ensw` exits. Keying on title alone merges four rooms into three and **makes every edge through them a lie**. CircleMUD reuses titles across the segments of a road; that is ordinary MUD authoring.
- **The residual is stated rather than hidden.** Two genuinely distinct rooms sharing both title *and* exits still merge; separating them needs the path taken to reach them. No collision in this corpus, and a larger map will have them.
- **Dark rooms are keyed by their entrance** — the room they were entered from, plus the direction — because `It is pitch black...` offers nothing to key on. Unique per entrance, so right for the edge even when wrong for the node. Two entrances to one dark room appear as two nodes: **a visible guess rather than a silent merge.**
- **The map measures its own coverage.** `unexplored()` reports advertised exits never taken — 24 rooms' worth — which is the guard against reporting a region as unreachable when it was only unvisited. **A map with no coverage measure invites exactly the wrong conclusion.**
- **Mermaid over Graphviz, and not because `dot` is missing.** Mermaid renders natively on GitHub, so the map drops into a README with no toolchain and no image file to keep in sync with the data.

## A bug the map found that the tests could not

- **`A Nexus | (n), (e)` in the coverage table was the tell.** CircleMUD parenthesises a **closed-door** exit — `[ Exits: n (e) s ]` — and the parser was carrying the parentheses through. Nine of them in the corpus.
- **It broke two things at once.** Coverage compared `(e)` against `e`, so **every door was reported as an exit never taken**; and room identity keys on the exit set, so **a door shut on one visit and open on the next would split one room into two nodes**. No collision had occurred — by luck, not design.
- **The fix keeps the signal rather than discarding it.** Exits are normalized and `doors` comes back as its own list: a closed door is where a player is *about* to be blocked, which is worth knowing before they try it.
- **Only rendering the data exposed it.** 130 tests passed over this parser, all against strings I had chosen. The bug appeared the moment output was laid out for a human to read. **A test asserts what you thought to ask; a rendering shows you what you did not.**

## Auditing against the brief, and two categories answered for free

- **Asking "do we meet the scenario?" was worth more than another feature.** Scored against the brief's own words rather than against the plan, the answer was **the machinery is complete and the agent has only ever walked around**. - **Two signals built for different categories describe the same experience.** Combat risk says the fights are trivial; the boredom metric says one session made 29 moves through 9 rooms at a 3.2× revisit ratio with an 8-move barren stretch. **Neither was designed to corroborate the other**, which is exactly why the agreement is worth something.
- **The `--watch` process had been deleting the evidence for an hour.** Started 15:57, before the progression parser existed. Python holds the modules it imported at startup, and this ingest **drops and recreates** — so the stale watcher did not merely fail to add progression events, it **removed them from a database that had been built correctly**, every ten seconds.
- **Nothing anywhere reported a problem.** The parser was correct on disk. Its tests passed. The ingest printed a cheerful row count. The dashboard refreshed. **A derived store rebuilt by stale code is indistinguishable from one rebuilt by current code, except in what it contains** — and only a query for something that should have been there exposed it.
- **The fix checks before rebuilding, not after**, because the rebuild is the destructive act: the watcher compares `boukensha/**/*.py` mtimes against its own start time and re-execs itself. **A convenience that runs unattended has to be able to notice it has gone stale**, or it quietly converts every future edit into data loss.
- Fourth instance this week of one shape: **a component confidently producing wrong output with no signal that anything is wrong.** The `ok` flag, the silent billable run, the auto-refreshing dashboard, and now the watcher.

## The interaction run: a finding, and a bug in the parser that found it

- **Confusion went from one message to four reasons.** 24 events: `not_present` ×19, `unknown_command` ×2, `cannot_take` ×2, `disabled_command` ×1. Rejections now carry a **reason** the way blocks do, for the same purpose — "the game has no such command", "that thing isn't here" and "you may not touch that" are three different player experiences and three different fixes.
- **The run caught a pattern that had never matched anything.** I had written `Huh?!?` from memory of CircleMUD; tbaMUD says **`Huh!?!`**. The pattern was syntactically fine, tested nothing, and silently matched zero replies for as long as it existed. **Second time in this one file** — the exit line was `[ Exits: n s ]` and I had written `Obvious exits:`, also from recollection. **Both drafts failed the same way and neither failed loudly.**
- **`unknown_command` is the gentlest failure in the set**, which is worth recording as a contrast rather than a defect: the game answers *"Huh!?! Did you mean: tell, take, track"* — it suggests alternatives. A refusal that proposes a next step is a different player experience from one that does not.

## Why the map is disabled — the week's argument in one finding

- **`map` returns "Sorry, the map is disabled!" in a world of 12,733 rooms.** Traced to source rather than reported as seen: `config.c:311` sets `map_option = MAP_IMM_ONLY`, and `asciimap.c:218` refuses any character below immortal level. The container has no `etc/config`, so the MUD runs entirely on compiled defaults.
- **The feature is not disabled. It is restricted to immortals, and the message misdescribes that.** A player is told something does not exist when it does, with no hint that a permission level is involved. **A misleading refusal is worse than a plain one** — it forecloses the next question.
- **Three claims needed separating, and only reading the source separated them:** our Docker setup did not disable it (the container adds no config); Arcane Loop did not disable it (nobody chose it); the *stock default* hides it from every mortal player and says the wrong thing. **The first two would have been wrong and confident.**
- **This is the whole week's constraint in miniature.** The agent observed a refusal. Whether that refusal was our environment, the operator's choice, or the software's default is exactly the attribution question — and no amount of telemetry answers it. **The instrumentation tells you what happened; it takes reading the code to say whose fault it is** — and a finding shipped without that distinction is a guess wearing evidence.
