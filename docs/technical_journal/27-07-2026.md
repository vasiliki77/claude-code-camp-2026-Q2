# 27-07-2026

## Step 1 (Struct Skeleton) — Ruby → Python Port

- Ported `week1_baseline/ruby/01_struct_skeleton` to `week1_baseline/python/01_struct_skeleton`. Step 1 defines the three plain data containers the agent passes around — `Tool`, `Message`, `Context` — with no logic yet, just the shapes.
- Step 0 (Configuration) had already been ported to Python earlier; step 1's Python folder was already a byte-for-byte copy of the step-0 Python folder, so the work was applying only the delta Ruby made between steps 0 and 1, not a port from scratch. This confirms the snapshot-per-step approach: each step folder is a self-contained copy of the previous one, edited in place, so it stays independently runnable and diffable against the step before it.

### What was ported

- **New modules:** `boukensha/tool.py`, `boukensha/message.py`, `boukensha/context.py`.
- **Edited:** `boukensha/__init__.py` (export `Tool`, `Message`, `Context`); `boukensha/config.py` (removed the now-unused `PROMPTS_DIR` constant); `examples/example.py` (rewritten to build a `Context`, register one `move` tool, add two messages, and print them).
- **Deleted:** the packaged `prompts/system.md` — step 1 ships no default prompt, mirroring the Ruby step. The example resolves its system prompt through the user override at `.boukensha/prompts/player/system.md` instead, so the packaged default was dead code.
- **New launcher:** `week1_baseline/bin/python/01_struct_skeleton`, invoking the shared repo-root `.venv` interpreter directly (no per-step venv).

### Design decisions

- **Ruby `Struct` → Python `@dataclass`.** Ruby defines `Tool` and `Message` with `Struct.new(...)`; a dataclass is the direct analogue (positional fields, generated constructor) and keeps the port line-for-line. `Context` stays a plain class in both, since it carries behaviour (`register_tool`, `add_message`), not just data.
- **`to_s` / `__str__` matched byte-for-byte** so a literal `diff` of the two programs' output is the verification gate for every port. Three subtleties this pinned:
  - Ruby's inclusive slice ranges `[0..40]` and `[0..60]` become Python's exclusive `[:41]` and `[:61]` (off-by-one).
  - The trailing `...` on a message is always appended, even when the content is shorter than the truncation length.
  - `Tool` renders its parameter keys in Ruby symbol form `[:direction]`, not Python's `['direction']`.
